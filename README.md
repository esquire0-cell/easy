# 릴리스 보관소

GitHub 릴리스에 올린 zip 을 판별로 남긴다.

⚠️⚠️ **`_배포/` 안에 두면 안 된다.** `배포준비.py` 가 시작할 때
`shutil.rmtree(_배포)` 로 **통째로 지운다** (`배포준비.py:235`). `dist/` 안도
마찬가지다 — `_배포` 아래는 전부 소모품이라, 다음 판을 묶는 순간 지난 판
zip 이 같이 사라진다. 그래서 여기(`_릴리스/`)에 둔다.

⚠️ **지난 판을 지우지 말 것.** 사용자가 새 판에서 못 쓰겠다고 하면 되돌려
줄 것이 있어야 한다. 자동 업데이트는 앞으로만 가므로, 되돌리려면 지난 판
zip 을 직접 보내는 수밖에 없다.

⚠️ 파일 이름은 판마다 **`EasyTest-win64.zip` 으로 같다.** 판 번호는 폴더
이름으로 가른다 — `index.html` 의 내려받기 단추가
`releases/latest/download/EasyTest-win64.zip` 을 글자 그대로 들고 가므로
파일 이름에 판 번호를 넣으면 안 된다 (08-19 실측: 릴리스는 200 인데
내려받기만 404).

             · **업데이트가 검은 창에서 멈추던 것** (제보 09-08). 갈아끼우기

             · `quit()` 은 부탁이지 끝내기가 아니다. 10초 안에 안 죽으면
               손수 끝낸다(`updater._죽기보증`). 상한만 있으면 갈아끼우기가
               **실패로** 끝나고, 이것이 있어야 **성공으로** 끝난다.

               아는 까닭(갈아끼우기·판 바뀜)만 걸렀는데, 자국은 '창을 내다
               안 돌아왔다' 일 뿐이라 백신·작업관리자·우리 taskkill·정전이
               다 같은 자국을 남긴다. 게다가 `살아남음` 으로 굳으면 그 검사
               조차 안 거쳤다. 이제 **까닭을 안 묻고** 5번 잘 켜지면 한 겹
               덜 벗고 되물어본다 — 헛자국은 0 까지 저절로 내려오고, 진짜
               크래시는 한 번 죽은 뒤 굳어 다시는 안 묻는다.
             · 우리가 치운 옛 판의 자국을 크래시로 안 센다.
             · **설정의 '안전 모드 풀기' 가 안 풀리던 것** (원래 있던 흠).

               도로 적었다. 한 판에 한 번만 적도록 문을 달았다.
             · 깨진 바탕화면 바로가기를 켤 때 고친다. 윈도우가 띄우는 말이
               **백신 경고와 글자가 같아**("지정한 장치, 경로, 파일에 액세스
               할 수 없습니다") 백신을 의심하게 되는 자리였다.

             ⚠️ 이 판의 고침은 거의 다 **수학·과학 시험지를 옮길 때**만
                드러나던 것들이다. 국어·영어는 원래 잘 되고 있었다.
             · **선택지가 통째로 지워지던 것** (`pdf_reader._drop_running`).
               머리말·꼬리말 걷어내기가 **후보는 자리로 뽑고 지울 때는 글자로
               문서 전체를 훑었다.** 과학탐구 답항은 `① ㄱ ② ㄴ ③ ㄱ, ㄷ …`
               로 글자까지 되풀이되므로, 두 쪽 아래 띠에 걸린 것만으로 꼬리말이
               되어 **문서 전체 6곳**에서 사라졌다 (20문항 중 6). 되풀이 기준을
               절반→4분의 3 으로 올리고, **띠 안에 있는 줄만** 지운다.
             · **밑줄이 `__낱말__` 로 인쇄되던 것** (`writer.상자에표가있나`).
               양식 상자는 찾아바꾸기로 채우는데 그 판단이 **수식만** 봤다.
               `[[ ]]` 가 대괄호째 찍히던 것과 같은 병인데 한쪽만 고쳐져 있었다.
             · **수학·과학은 밑줄·빈칸·상자가 통째로 죽어 있었다.** 세 곳이
               `page.extract_text()` 를 **쪽 전체로** 재서 수식이 한 귀퉁이만
               있어도 그 쪽을 건너뛰었다. 이제 **조각마다** 잰다
               (`pdf_reader.글이깨졌나`). 열자마자 쏟아진 헛밑줄(분수선·표
               테두리)은 `_아래가붙어있나`·`_표괘선빼기` 로 막았다 — 잣대를 넷
               재 보고 셋을 버렸다 (선폭비·세로괘선·이웃 수식글자는 다 겹쳤다).
             · **원본 대조가 수학·과학에서 꺼져 있던 것** (`pdf_verbatim`).
               PUA 2% 문턱이라 물리 5.1%·화학 9.9% 가 통째로 접혔고, <보기>가
               원본과 달라도 **'확인필요 0' 으로 조용히 나갔다.** 수식 글자만
               지우고 견주게 하고 문턱을 20% 로 올렸다.
             · **제시문이 <보기> 상자로 들어가던 것** (`pdf_box`). 채우기가
               `q.지문` 만 채우고 `q.보기박스` 는 한 번도 안 채워서, 발문이
               <보기>를 가리키면 쓰는 쪽이 지문을 <보기> 상자에 넣었다.
               말머리로 갈라 제자리에 넣는다. 줄글 상자는 이어 붙이고 항목
               상자는 줄을 지킨다 (원본의 인쇄된 줄이 우리 단 폭과 안 맞는다).
             · **상자 열 맞춤** (`writer.paste_box`). 붙여 온 상자의 문단 정렬을
               붙인 **뒤에** `go_writing_end` 로 걸어서, 상자가 마지막 문단이
               아니면 엉뚱한 데 걸렸다 — 제시문이 앞에 있는 문항만 9.71pt
               어긋났다. 붙이기 **전에도** 못 박는다. `spike_boxalign.py` 로
               재서 0.00pt 확인.
             · **글자가 깨져 나오던 것들** — `기숙`·`니은`(자모 이름),
               `기호 ㄱ`, `ᆨ`(U+11A8 붙임꼴 — 작게 찌그러지고 수식으로까지

               삼킨 것), 수식 속 `[[`(겹친 표), 짝 안 맞는 괄호.
             · **선택지가 그림인 문항** — `(그림)` 으로 자리를 잡고 알린다.

                  멀쩡한 줄이 어긋난 것으로 잡힌다.
             · **알림이 경고로 보이던 것** (`옮긴문항.알림`). `미심쩍은가` 가
               `주의` 하나만 보므로, '원본에서 가져왔습니다' 같은 좋은 소식을
               거기 담으면 그 문항이 통째로 ⚠ 로 물든다 (사용자 지적 "이 문구는
